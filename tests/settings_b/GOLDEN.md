# Frozen migration inventory

`v1-r2-ps1-rows.tsv` was generated from the **4067397a** navigator and component copied by `git show` into `tests/settings/fixtures/v1-r2/`. The snapshot changes only exported identifier prefixes, its include path and a forward declaration; it never builds into BreadBox. `golden-v1-r2.c` is the extraction harness. The ordinary gate **does not regenerate** the golden file: it reads the production Settings B adapter via `candidate-ledger.c` and compares all 484 ordered labels, including binding rows, in Old/New × system/untested game/tested game × debug off/on contexts. New top-level shared-hotkey duplicates and the new Cheats action are checked separately and excluded from the old-row inventory. The old navigation/spec harnesses explicitly use the frozen snapshot to retain config/input compatibility coverage; they do not certify the new UI.

`v1-r2-gba-rows.json` was extracted from `git show 4067397a:systems/gba/gba_settings_ui.c` and `app/ui/bb_controls.c`; their full-source SHA256 values are recorded. It covers Old/New × system/ordinary/solar game, plus physical mappings and shortcuts. The explicit renames are old **Controls** → new **Button mappings** (adapter row 200) and, on both systems, the shortcut rows **Fast forward** / **Rewind** → **FF keys** / **Rewind keys** (distinct from the touch-slot names; mapped back in `gba.c` and `candidate-ledger.c`); new touch/FPS/side/Cheats rows have separate production assertions.

**Settings overhaul.** `inventory.py` replaces the plain diff: every frozen row must still be in its system's list, in order, except the shared shortcuts, which moved to their one home, **Settings > Customize**: PS1 `Bottom-screen buttons` (model; on Customize **Touch buttons**, an explicit rename: the old label is cut beside its value) and the binding rows `Fast forward` / `Rewind` (FF keys / Rewind keys), GBA's `Fast forward` and the `Rewind` after it (FF keys / Rewind keys). Each moved row must be on the Customize page the production shell builds for that console (`model.c` prints it) and in no system list; Customize may hold nothing else but the room's own rows. In a running game the pause card owns Cheats (both systems) and GBA's Button mappings, so they are not repeated in the game's list (`ps1.c`, `gba.c`); the frozen contexts are not running, so the frozen rows are unchanged.

Never update the expectations from the candidate. A lost or renamed old row fails the frozen comparison.
